1. Dynamic Controls. Финальное состояние через expect(), не spinner через wait_for

В этом репозитории UI ждут через expect(): он сам повторяет проверку, пока не совпадёт. locator.wait_for(state="visible") на #loading:visible обязан поймать промежуточный кадр. Лоадер мелькнет быстрее таймаута - тест упадёт, хотя конечный результат верный.

Вместо такого:

controls.remove_checkbox()
controls.wait_for_checkbox_loading()
controls.wait_for_checkbox_loading_finished()
expect(controls.checkbox_message).to_have_text("It's gone!")

лучше так:

controls.remove_checkbox()
expect(controls.checkbox_toggle_button).to_be_disabled()
expect(controls.checkbox_loading).to_have_text("Wait for it...")
expect(controls.checkbox).to_be_hidden()
expect(controls.checkbox_message).to_have_text("It's gone!")
expect(controls.checkbox_toggle_button).to_have_text("Add")
expect(controls.checkbox_toggle_button).to_be_enabled()

Локатор лучше без CSS :visible: self.checkbox_form.locator("#loading"). Видимостью пусть занимается Playwright.

remove_checkbox и add_checkbox оба кликают одно и то же. Имена врут, если на кнопке уже Add, а вызываешь Remove. Два локатора по роли:

self.remove_button = self.checkbox_form.get_by_role("button", name="Remove")
self.add_button = self.checkbox_form.get_by_role("button", name="Add")

Так же Enable и Disable. Сейчас get_by_role("button") без имени. В форме появится вторая кнопка - сломается.

В test_checkbox_can_be_added после Add не видно, что кнопка снова enabled и лоадер исчез. Добавь.

2. Hovers. «Переключение caption» никуда не переключает

test_only_hovered_user_information_is_visible наводит только на user1 и смотрит, что 2 и 3 скрыты. В Scenario 4 ты сам написал switching. Нужен шаг: hover(0) - видно user1, hover(1) - user1 hidden, user2 visible.

Имя теста: test_info_hidded_before_hover поправь на hidden.

Тройку и строки "name: user1" вынеси в константы, как EXPECTED_TITLE в tests/test_main_page.py.

open_profile() после клика оставляет тот же объект страницы. В проекте навигация отдаёт POM: MainPage.go_to_login_page() приводит к LoginPage. Достаточно return self.page, ещё лучше завести UserProfilePage с path и проверкой, что /users/1 это 404 «Not Found». Проверка одного URL годится как дымовая, но стенд профиль не рисует. Это расхождение - одна строка в README, по тому же принципу, что /security и /secure.

3. conftest.py. Хук скриншотов не видит новые POM

_page_from_item ищет только main_page, login_page, secure_page. Повесишь @pytest.mark.critical на новые тесты - Allure останется без скриншота. Допиши hovers_page и dynamic_controls_page в тот же кортеж.

4. Конвенции репозитория, не блокеры

  • Маркеры. В старых тестах есть e2e, у новых только ui/regression/positive. Вешать positive на весь файл с Remove и disabled странно. Отдельные маркеры hovers и dynamic_controls в pytest.ini не обязательны, без них набор не вырежешь командой вроде pytest -m login.
  • test_enabled_text_input_accepts_value: у value нет type hint. Enable крутится три раза, примерно по 5 секунд, ради разных строк. Один enable и parametrize только на fill выйдет дешевле.
  • Нет проверки, что disabled input не принимает ввод. to_be_disabled() в init уже есть, добавь fill и ожидание ошибки или пустого значения.
  • Секции тоже не разведены. Remove чекбокса не должен включать input.
  • docs/test-task.md это исходное ТЗ домашки. Свои сценарии лучше положить отдельным файлом в docs/ или только в README, чтобы не смешивать с чужим заданием.
  • README не обновлён: структура, покрытие, /users/N отдаёт 404.
  • Коммит style: align BasePage formatting это пустая строка. К задаче не относится.

5. Мелочи по локаторам Hovers

.figure и .figcaption h5 живут, семантики мало. Внутри фигуры можно get_by_role("heading") - ближе к приоритету get_by_role из правил проекта. Аватары (img / alt) нигде не проверяются.

Что покрыто, чего не хватает

Hovers. Есть init, hidden, hover на трёх, unhover, URL профиля. Нет смены hover с 0 на 1, картинок, 404 профиля, ссылки с главной.

Dynamic Controls. Есть init, check, remove, add, enable с fill, disable с сохранением значения. Нет ввода в disabled, независимости секций, enabled после Add.

Прямой HoversPage.open(), а не клик с главной - так же сделаны login_page и secure_page. Для этой задачи хватает. Тест «ссылка Hovers есть в каталоге» был бы бонусом, не требованием.
